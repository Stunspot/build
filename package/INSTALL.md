# Install BUILD v0.1.0

You need a Codex host that can read local files and install user skills for the durable installation route. The complete package contains a `build` directory with `SKILL.md`, metadata, references, assets and bundled workflows. Keep that directory intact.

## Install and check discovery

1. Extract the complete BUILD release ZIP to a folder you can find again. Confirm that `build/SKILL.md`, this `INSTALL.md` and `README.md` exist.
2. Give Codex access to the extracted folder and send this installation request. On a folder-based Codex host, install the **complete `build` directory** in its user skill root under the same name. Inspect any existing installation and retain a recoverable backup before an authorized replacement.
3. Ask the host to read the installed entrypoint through its actual discovery route and report the installed location and version. If it requires a refresh or a new chat, follow that route and check again.
4. Verify that BUILD can identify its bundled CONCEIVE and BRAID entrypoints. Do not install those nested snapshots as duplicate skill entries.

```text
Install BUILD from this extracted release as a Codex skill. Preserve the complete build folder and its resources. Inspect any existing version and keep a recoverable backup before replacing it. Then read the installed entrypoint through the host's discovery route and report its location, version, and whether BUILD, CONCEIVE and BRAID can be found. Do not launch collaborators or schedules yet.
```

Installation is complete when the installed entrypoint is read and the three workflows are found. A copied folder alone does not establish discovery. Installation creates no collaborator chats, schedules, spending or public publication.

If durable installation is unavailable, identify that limit. A chat that can read the complete extracted files can use the method within the session and the host's actual capabilities. Attaching a ZIP alone is not permanent installation; a host that cannot read it needs the extracted resources made available.

## Try it before a full launch

```text
Use BUILD to explain how you would approach this idea: [your idea]. Do not create chats, schedules or files yet.
```

Expect the understood goal, available collaboration mode and next step. On compatible hosts, `$build` explicitly invokes the skill. You can also request CONCEIVE or BRAID directly; BUILD routes to the respective bundled workflow.

## Launch the full workflow

The following named command requests **five communicating design chats followed, when ready, by three execution chats and one recurring SUPERVISOR check normally every ten minutes until completion**. Your narrower instructions control; add `Do not schedule unattended supervision` if that is your boundary. Multiple contexts and recurring checks use your host's capacity and model allowance.

```text
Create a BUILD called [name]: [the outcome you want designed and made].
```

Preserve the user's actual creation and communication authorization in each participant brief. The composed BRAID phase takes its authority from this BUILD request; it does not imply a separate BRAID invocation. If native chats or scheduling are unavailable, the host must state the exact limit instead of claiming active collaboration or unattended supervision.

## Recover, update or remove

If discovery fails, ask the host to locate `build/SKILL.md`, check that the complete directory was copied, and repeat the supported discovery route. Preserve the extracted package while resolving the issue. If work was interrupted, recover the existing record, collaborators and schedule before creating replacements.

For an update, keep your project records and a recoverable copy of the existing skill, replace the complete skill directory from the intended release, then repeat discovery. To remove it, ask the host to identify and remove only the installed BUILD skill. Removing the folder does not stop existing chats or schedules; explicitly pause or cancel those when intended, while preserving the artifacts you need.
