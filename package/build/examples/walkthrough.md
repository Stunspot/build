# A small teaching tool, carried into making

Illustrative walkthrough, not a recorded multi-agent trial.

The owner asks for an offline vocabulary practice tool for an adult learner who tires easily. A first idea is a flashcard grid. CONCEIVE notices that the decision is not merely a grid layout: the learner needs a tolerable practice loop and a useful stopping point. Taylor proposes a tiny conversational scene; Alex points out that content entry cannot become a second job; Calvin asks how the learner can distinguish recognition from recall; Nathan preserves a way to change topics without rebuilding the tool. Morgan combines a short recall exercise, a reveal-and-rate step and an optional scene, with one importable plain-text word list.

The design handoff preserves the offline constraint, keyboard access, editable vocabulary, voluntary stopping and a small progress signal. The scene is an optional experiment, not a required dependency. A maker can implement the core loop first. CHECKER can challenge whether the learner can actually add words and complete a session without the mouse, rather than merely checking that a webpage renders.

BUILD passes that full design and its uncertainty to BRAID. If implementation shows that the proposed import format loses accented characters, MAKER returns the evidence to the relevant design question and repairs the format without reopening the whole learning philosophy. CHECKER examines the changed import behavior. Completion is a usable, checked tool at the authorized delivery surface, not eight chats announcing that they agree.

## A result that should not enter BRAID

The same method may discover that the learner already has a suitable tool but cannot find its offline setting. A well-supported explanation or configuration change can satisfy the real purpose. BUILD does not manufacture a new product to justify its own name.
