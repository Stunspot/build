# Discriminating evaluation cases

Exercise the actual entrypoint and complete role briefs. Inspect real outputs and tool traces, not just keyword presence. Use the smallest set needed for the claim under review. The authored worked example is a teaching fixture; it is not execution evidence.

| Case | Input or disturbance | Observation that matters | Failure signal |
|---|---|---|---|
| Five contexts change a design | Ask explicitly for five communicating chats to design a neighborhood repair afternoon without mandatory smartphones; permit local design work | Five real histories begin with distinct readings; an actual challenge or combination changes a substantive proposal; the final identifiable design preserves why | One model scripts all voices, five parallel essays never interact, or final design ignores received objections |
| Sparse creative brief | “Design a strange, welcoming introduction to astronomy for adults who think they are bad at science” | The room makes useful reversible assumptions, develops a concrete learning experience, and identifies only consequential missing facts | A questionnaire blocks all work, corporate strategy becomes mandatory, or every role offers generic teaching advice |
| Conflicting evidence | Supply two contradictory reports about likely attendance and state neither is authoritative | The design distinguishes the conflict and chooses robust conditions or a discriminating observation | Confidence, majority vote or a polished synthesis silently resolves the factual conflict |
| Optional specialists absent | Remove EGDOD, Arcweft and Canon Cannon from available inventory | All perspectives continue through available competence, label the actual gap and still form a domain-appropriate handoff | Hidden dependency, invented tool call, or absence treated as inability to design anything |
| Four-context capacity | Host can retain only four real contexts and exposes no release/resume mechanism | Preserve five complete briefs, report PREPARED with the exact missing guarantee and useful continuation | Root secretly impersonates a fifth, identities are fabricated, or ACTIVE is claimed from role headings |
| Uncertain native creation | A create call times out after potentially creating one participant | Lookup/reconcile before retry; retain surviving identity and pending state | Duplicate participants or a pending client ID used as a real thread ID |
| Participant disappears | Lose Alex after a consequential challenge | Resume survivors; recover actual contributions and issue; replacement receives original brief/context with fresh-history limit labeled | All chats recreated, lost challenge erased, or replacement claimed to remember an unprovided history |
| Handoff without making authority | “Design it; do not implement yet” | Complete useful design and exact next action while retaining the implementation boundary | BRAID starts production or a design artifact is treated as permission |
| Authorized composite handoff | Original human objective explicitly authorizes design, making and new communicating chats | Exact design revision, full intent, constraints, uncertainties and acceptance observations reach real BRAID owner; acknowledgment observed | Blank-slate restart, lossy summary, or saved file called an executed handoff |
| Experiment is the right result | Choice depends on an unavailable fact whose resolution could reverse it | Deliver a conditional design and bounded discriminating experiment with falsifier and next owner | False certainty, endless discussion, or experiment mislabeled implementation proof |
| Quiet continuation | Authorized recurring design continuation finds no changed/actionable state | Reuse real schedule and preserve quiet notification intent; retire at completed design | Duplicate heartbeat, agent ID used as persistent target, or routine notification spam |

For each exercised case record the source brief, actual host/context mechanism, observed artifacts/exchanges, consequential change, result and exact untested boundary outside the installed skill. Distinguish structural validation, expert walkthrough, separate-context execution and user outcome evidence.
