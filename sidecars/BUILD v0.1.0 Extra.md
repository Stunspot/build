# Description

BUILD carries an idea from design into making, checking and supervision. It joins CONCEIVE’s five-context design discussion with BRAID’s three complementary responsibilities: MAKER makes, CHECKER independently checks, and SUPERVISOR keeps the effort moving toward the intended result.

The bridge between those phases preserves the substance. The chosen design travels with the original purpose, constraints, material decisions, assumptions, unresolved conditions and observations that define success. BRAID can improve the means of implementation while keeping the user’s settled commitments intact. If making reveals a problem with an important design choice, BUILD returns that question and its evidence to the design contexts, then brings the revised decision forward without restarting unrelated work.

Start with an idea that needs to become a finished thing, or provide a design already ready for execution. BUILD gives the unresolved parts the design attention they need and can take a settled design directly to BRAID. Its package includes complete, attributed snapshots of both workflows, so a missing sibling installation does not break the method. A current installed workflow can be selected when available, with the governing version recorded.

# Usage Notes

Copy the .zip from "Additional Files" to your Codex, Claude Code, or other harness, or add the .zip to a project knowledge base in Chat. Attach or reference the .zip in chat and say, "Install this skill." The prompt in this post is optional.

- Include what should exist at the end, relevant existing work, constraints and the authority to implement it.
- The explicit named launch creates five CONCEIVE design chats followed, when ready and authorized, by three BRAID execution chats with one recurring SUPERVISOR heartbeat, normally every ten minutes until completion. The actual BUILD request authorizes that composed phase; narrower instructions still govern.
- A settled design can go directly to BRAID; an explicitly requested five-context design collaboration is preserved.
- The host supplies real participant contexts, coordination and any scheduling. Prepared briefs remain usable when those facilities are limited.
- A design-only request does not become permission to implement, spend, publish or destroy.
