# Install and start BUILD

[BUILD home](https://stunspot.github.io/build/) · [Choose a workflow](use.md) · [Recovery](recovery.md)

This guide applies to BUILD 0.1.0. You need Codex with permission to read local files and install user skills for the durable installation route. Native collaboration also needs the host's actual chat, communication and scheduling tools. BUILD supplies the method and bundled workflow instructions; the host supplies execution.

## Install in Codex

1. [Download BUILD v0.1.0](https://github.com/Stunspot/build/releases/latest/download/BUILD-v0.1.0.zip) and extract the ZIP to a folder you can find again. Open it and confirm that `build/SKILL.md`, `INSTALL.md` and `README.md` exist. Keep all nested references and assets.
2. Give Codex access to that extracted folder, then send this installation request. Codex should inspect any existing installation, preserve a recoverable backup before an authorized replacement, and install the **complete `build` directory** under that name in its user skill root. Do not install the nested CONCEIVE and BRAID snapshots as duplicate skill entries.
3. Ask Codex to read the installed `build/SKILL.md` through its actual discovery route and report the installed location. If the host requires a new chat or refresh before discovery, do that and repeat the check. A copied folder alone does not prove discovery.
4. Confirm it can find BUILD and the bundled CONCEIVE and BRAID entrypoints. Try the request in [First look](#first-look-understand-the-method) before committing to a full launch.

```text
Install BUILD from this extracted release as a Codex skill. Preserve the complete build folder and its resources. Inspect any existing version and keep a recoverable backup before replacing it. Then read the installed entrypoint through the host's discovery route and report its location, version, and whether BUILD, CONCEIVE and BRAID can be found. Do not launch collaborators or schedules yet.
```

**Installation is complete when:** Codex reports the installed version and location, reads the installed entrypoint, and can identify all three workflows. Installation itself creates no collaborator chats or supervision schedule. If durable installation is unavailable, use [the session route](#use-the-package-in-another-chat) or stop at the preserved extracted folder.

## First look: understand the method

Use a small idea you can assess:

```text
Use BUILD to explain how you would approach a small offline vocabulary practice tool. It should take an editable word list, work with a keyboard, and allow the learner to stop at any time. Do not create chats, schedules or files yet.
```

Expect an explanation of the design and execution phases, the resources your host can actually provide, and an appropriate next step. If BUILD is not found, use [the discovery recovery path](recovery.md#build-is-not-found).

## First full BUILD

The `Create a BUILD called` command requests **five communicating CONCEIVE design chats**, then **three BRAID execution chats** when ready, including **one recurring SUPERVISOR check normally every ten minutes until completion**. These use your host's capacity and allowance. Include a narrower limit before launching if needed; for example, `Do not schedule unattended supervision`.

```text
Create a BUILD called Vocabulary Lab: design and make a small offline vocabulary practice tool. It should accept an editable word list, work with a keyboard, and let the learner stop at any time. Keep the first version small. Do not publish it or use paid services.
```

Expect an initial account of the outcome, scope, collaboration mode, actual participants, shared record and supervision state. If the host lacks persistent chats, scheduling or capacity, BUILD should state the limit and use only the fallback it can support. It must not call five briefs five active contexts.

During design, you should receive a coherent proposal with reasons and material uncertainty. The making phase should use that identifiable design, and the final artifact should match the revision independently checked. A launch notice is progress, not completion.

## Use the package in another chat

Extract the complete package and make the relevant files available to a chat that can read them. Ask it to read `build/SKILL.md` and the resources required for your chosen workflow. Attaching the ZIP is sufficient only if that host can extract and read its contents.

This is **session use**, not permanent installation or a verified native integration. A chat without separately addressable contexts cannot provide the promised independent collaboration merely by writing several role labels. It can explain the method or prepare briefs; it should identify what it could actually execute.

## Update or remove

For an update, retain your project records and a recoverable copy of the existing skill folder, then install the complete replacement from a tagged release and repeat the discovery check. Keep an ongoing BUILD on its recorded workflow revision unless you deliberately choose to change it.

To remove BUILD, ask your host to locate the installed `build` skill and remove that identified installation. Keep project artifacts separately. Inspect any live collaborator chats and supervisor schedule: removing a skill folder is not a request to stop or delete those. Explicitly cancel or pause ongoing work and its schedule when that is your intent.
